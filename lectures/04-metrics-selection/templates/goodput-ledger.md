# Goodput 口径表

## 先把一批运行锁住

固定批次口径：开测前冻结业务运行清单，用 Task ID（业务标识）关联工单，用 Run ID（运行标识）区分重复试验；运行内部的重试保留原 Run ID，每次运行在 Goodput 分子里至多出现一次。

批次窗口从首笔业务提交开始，到清单里全部运行到达预定终态结束，包含业务排队、执行和重试。单笔成功业务计到约定答复交付，失败、超时和取消分别记录终点；交付前必需的验证计入等待，事后离线评测只回填判定、耗时单列。

| 字段 | 定义与单位 | 复核要求 |
|---|---|---|
| N | 冻结清单中的业务运行总数，次 | 失败、超时、取消、未验证记录全部保留，不事后删除慢业务 |
| T | 首次提交至全批约定终态的窗口时长，秒 | 大于零；保留起止时间戳，全部运行到终态后才发布最终值 |
| B | 达到业务目标的运行数，次 | 对照工单判据与结果证据，不用流程正常结束代替业务完成 |
| Q | 同批满足质量、时延、安全三项要求的运行数，次 | 每次运行去重计数，保留判据版本和证据位置 |
| C | 同批全部运行的总执行成本，统一币种 | 包含失败、重试及不达标运行；用量、单价、分摊规则齐全 |
| 业务级 Goodput | Q ÷ T，业务/秒 | 未验证记录不计入 Q；证据未齐时只报暂定统计 |
| 成功业务成本 | C ÷ Q，货币/业务 | Q 为零时报告“无合格业务”和总成本，单位成本记为不可计算 |

## 每个达标判断，都留一份证据

一笔业务要算合格，得同时通过三关。Agent 这里的合格要答对、够快、没越权，三关过完才算数。

| 约束项 | 配送查询工单检查什么 | 判定证据与计数方式 |
|---|---|---|
| 质量 | 业务目标已达成，且满足约定的事实准确性、完整性等要求 | 核对指定订单的物流快照、最终答复和评测结果；缺证据记未验证 |
| 时延 | 从约定提交起点到交付或其他终态，是否满足单笔时延门槛 | 保留业务时间戳；另按 SLO 检查全批达标比例与时延分布 |
| 安全 | 是否满足权限和信息披露等既定约束 | 保存 Guardrail（安全护栏）检查结果、实际交付内容及相关记录 |
| 成本 | 单笔上限、批次预算或成功业务成本是否达标 | 按事前选择的预算口径检查；不改变 Q，另给成本结论 |

## 换算核对

```text
原始业务吞吐 = N ÷ T
业务完成率 = B ÷ N
完成业务中的其余约束达标率 = Q ÷ B
业务级 Goodput = (N ÷ T) × (B ÷ N) × (Q ÷ B) = Q ÷ T
成功业务成本 = C ÷ Q
```

B 为零时直接报告 Q = 0、Goodput 为零，不计算 Q ÷ B。全部指标必须来自同一批记录。
