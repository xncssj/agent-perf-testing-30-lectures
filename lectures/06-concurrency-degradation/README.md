# 第 06 讲配套资料

本讲主题：并发还没有到峰值，为什么 Agent 已经开始退化？

本目录提供 5 份核心模板与 3 份补充填写表，包含参考定义、已知读数与待测边界。课程正文请在专栏阅读；本目录不包含项目源码、逐笔原始数据或可执行压测脚本。

## 使用方式与口径

1. 先登记统计对象、测量边界、单位与算法、统计窗口、判据及版本，再填写项目读数。
2. 同时记录设置并发、实际到达率和实际在途业务数。参数上升不能替代实际施压上升。
3. 业务台账沿用第 04 讲：运行总数 `N`、窗口秒数 `T`、达到业务目标的运行数 `B`、质量、时延和安全同时达标数 `Q`、全批总执行成本 `C`。有效吞吐为 `Q ÷ T`；成功业务成本为 `C ÷ Q`，`Q＝0` 时不计算单位成本。未验证的运行不能计入 `Q`，重试不能重复计为新业务。
4. 课程示例中模型放大约 2.65、工具放大约 1.65、重试放大 1.0 都只是单批单点，没有按负载档位统计。并发换算参数尚未实测回填，开放负载未运行，3 个示例案例未采集队列读数；不能据此填写实测安全容量。

## 参考章节与使用说明

- 参考课程第 06 讲“并发统计有四个层级”“Agent 自己给自己加压”“退化信号有四类，谁先到要看系统”“并发怎么加才对：五种负载模型”“这两份资产，后面在哪里用”。各模板列出对应章节与表名。
- 5 类模板分别用于登记负载层级、调用放大、负载模型、容量风险及并发换算参数；填写时应保留统计口径与证据位置。
- 容量阶梯图适用于该真实模型实验轮次，逐档判定、整轮判定及其他轮次应分开记录。
- 有效吞吐走平只作候选拐点，需核对实际负载上升、持续观察、质量与时延约束及队列证据；错误出现顺序依系统而定。
- 历史批次的限制：案例 1、2 的旧容量脚本在设置 30、50 线程时实际在途仍为 20 笔，走平可能来自脚本；案例 3 的高并发批次仅聚合 150/240 笔（62.5%），待修待测。它们不能与本图的新轮次混作同一组证据。
- 填写区用于登记本项目读数与证据。完成业务数不自动等于合格业务数；没有实测依据的字段应标明待采或待测。
