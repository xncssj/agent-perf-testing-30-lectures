# 三路径对照表

参考课程第 09 讲“先跟着一笔工单走一遍”中的“三路径对照表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 三路径对照表

| 层次 | 回答的问题 | 示例落点 | 本项目填写 |
|---|---|---|---|
| 业务处理路径 | 用户提交什么、系统交付什么终态 | 提交问题 → Agent 处理 → 合格答复／澄清／建议联系人工 |  |
| Agent 执行路径 | 决策、工具、模型、循环怎么串 | 阶段一规划循环选工具；阶段二扇出协作；阶段三工作流节点加检索 |  |
| 技术部署路径 | 进程、依赖、观测放在哪 | 本机一个进程全包；正式压测时段云端四机加统一网关 |  |

## 每层要圈出的位置

| 层次 | 必须标注的节点 | 容易漏掉的地方 |
|---|---|---|
| 业务处理路径 | 终态出口：合格答复、反问澄清、建议联系人工 | 把“建议联系人工”写成系统已经创建人工工单 |
| Agent 执行路径 | 决策循环、工具串行等待、模型调用次数、用户澄清、重试与数据存取 | 只压接口，看不见调用放大 |
| 技术部署路径 | 发压机、被测机、依赖机、观测机、统一网关、出网代理 | 把“机器分开”当成“资源不争” |

## 三层对齐检查

1. 每一笔业务能否同时落到业务终态、执行节点与部署机器上。
2. 业务采样点是否只在终态出口，而不是中间某次 HTTP 200。
3. 决策循环、工具等待、模型调用、澄清、重试五处是否都在执行路径上标出。
4. 网关、发压工具、出网代理是否注明共驻关系。
5. 观测旁路是否单独标出，是否承认其采集与上报开销仍占被测机资源。

## 判定边界

- 部署图回答“东西装在哪”，测试范围回答“压力打在哪、结论为谁负责”，两者不是一张图。
- 三阶段共用同一套业务对象与判定口径，变的是执行路径，不是另起一套业务。
- 本表只做路径对齐，不代表任何节点已经通过性能验证。
