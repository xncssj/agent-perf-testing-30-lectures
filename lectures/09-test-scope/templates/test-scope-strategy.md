# 测试范围策略表

参考课程第 09 讲“哪些真压、哪些用 MOCK、哪些只看着”中的“范围节点表”与“压测策略表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 范围节点表

| 节点 | 为何进范围 | 画错时会怎样 |
|---|---|---|
| 决策循环轮次 | 工具返回后再决策，时延与 Token 一起涨 | 只压接口，看不见调用放大 |
| 工具串行等待 | 订单查完再查物流，墙钟叠层 | 把下游空闲误当成 Agent 很快 |
| 模型调用次数 | 规划与生成都可能调模型 | 用 HTTP 200 次数冒充业务完成 |
| 用户澄清 | 模糊工单应澄清而非瞎答 | 澄清样本被当失败洗掉 |
| 重试与数据存取 | 重试放大负载，快照库承载业务取数 | 把存储竞态或重试放大算成“模型变慢” |

## 压测策略表

每个组件只选一种策略：真实压测、MOCK 压测环境（Stub／Mock）、只监控。

| 组件 | 策略 | 理由与边界 | 本项目填写 |
|---|---|---|---|
| Agent 服务（接口、运行循环、预算、工具池） | 真实压测 | 被测系统本体，SLO 全冲它来 |  |
| 订单／物流／知识工具及其快照数据 | 真实压测 | 工具取数的真实落点；数据是复制定版快照，不打生产库 |  |
| 业务快照数据存储 | 真实压测（随被测） | 并发竞态、连接问题在这里现身 |  |
| 澄清／重试路径 | 真实压测（样本覆盖） | 模糊工单与失败重试要进场景 |  |
| 模型 Provider | MOCK 模型为正式压测时段，真实模型重新执行 | 两种读数不可混记 |  |
| TTFT／TPOT | 专项真实采集 | 非流式窗采不到，用流式专项脚本单开窗口 |  |
| Java 订单物流服务 | 可选口径，二选一 | 在链路内或进程内直读，切换必须重跑基线 |  |
| 统一网关与鉴权 | 正式时段真实经过，对照待补 | 发压一律走网关链路；直连对照未执行要登记 |  |
| 观测栈 | 只监控 | 只拉数据不吃压力，自耗另记账 |  |
| 前端工作台 | 不压 | 非本课性能对象 |  |
| 生产业务系统与真实用户流量 | 隔离红线外 | 压测流量不得触达生产 |  |

## 策略选择检查

1. 每个组件是否只选了一种策略。
2. 选“MOCK”的组件是否写明绝对时延不代表真实模型。
3. 选“只监控”的组件是否写明自耗另账、不参与业务门禁。
4. 范围外组件是否写明“不归因”，而不是“不关心”。
5. 切换链路（进程内直读 ↔ HTTP 调 Java 服务）后是否重跑基线。

## 判定边界

- 被测系统边界，等于你要对其 SLO 负责的那一段。
- 外部依赖要么用可控快照和 Mock 固定行为，要么只监控并在报告里声明不可归因。
- 部署图不等于测试范围；范围画错，后面所有数字都在给错的对象背书。
