# 第 09 讲配套资料

本讲主题：模型、查询工具和业务系统组成一条链，测试范围应该画到哪里？

本目录提供 4 份模板，对应正文中的三路径对照表、范围节点表、压测策略表、指标落点表与风险清单表。本目录不包含正文图片、项目源码或逐笔原始数据。

## 模板

| 模板 | 用途 |
|---|---|
| [三路径对照表](templates/three-paths.md) | 把同一笔业务拆成业务处理、Agent 执行、技术部署三个视角 |
| [测试范围策略表](templates/test-scope-strategy.md) | 每个组件只选真实压测、MOCK 压测环境、只监控之一，并写明理由与边界 |
| [SLO 指标落点表](templates/slo-evidence-map.md) | 逐行核对每条 SLO 的采集位置与范围策略提醒 |
| [范围风险清单](templates/risk-checklist.md) | 把组件边界上的风险登记成清单，写清交给谁、当前证据状态 |

## 使用方式与证据状态

1. 先画三层路径，再标三种策略；部署图不能直接当测试范围。
2. 每条 SLO 都要能落到采集点；落不上的空行进风险清单，不留在“以后再说”。
3. Mock 只隔离模型波动，Mock 绝对时延不代表真实模型；两种读数分列。
4. 切换链路（进程内直读 ↔ HTTP 调 Java 服务）必须重跑基线，旧数据作废。
5. 范围外组件写“不归因”，不是“不关心”；观测栈自耗另账。
