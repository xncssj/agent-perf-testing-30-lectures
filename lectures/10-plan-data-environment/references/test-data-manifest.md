## 工单字段字典（v2）

| 字段 | 消费阶段 | 说明 |
|---|---|---|
| `ticket_id` / `user_id` / `user_query` | 全部 | 工单标识与用户输入 |
| `order_id` | 全部 | 关联订单号；无关联订单时为空字符串 |
| `expected_intent` / `expected_tools` / `difficulty` | 阶段一 | 意图、期望工具序列、难度 |
| `expected_answer_keywords` | 全部 | 答复必须全部命中的业务要点词，AND 语义 |
| `expected_facts` | 全部 | 结构化事实：订单号、状态、当前位置、预计送达、金额 |
| `expected_behavior` | 全部 | 行为特征文本，例如模糊工单须提示提供订单号 |
| `expected_agents` | 阶段二 | 期望参与的 Agent 集合 |
| `expected_path` | 阶段三 | Workflow 期望节点序列 |
| `expected_branch` | 阶段三 | 期望分支：自动答复／人工转接／澄清 |

判定优先级：`expected_facts` 与 `expected_answer_keywords` 全部命中为“结果合格”；两者均空的模糊工单回退 `expected_behavior` 判定。

## 各阶段消费方式

- 阶段一：压测脚本按工单集轮换输入；服务端种子数据读取订单、物流与知识库快照。
- 阶段二：适配层按 `expected_agents` 校验参与 Agent 与扇出路径。
- 阶段三：适配层按 `expected_path` 与 `expected_branch` 校验分支覆盖与关键路径。

## 使用要求

1. 任何再生成都会改变分布，旧基线作废并重采。
2. 每窗记录数据版本、条数与输入分布；未核对时不得声称业务代表性。
3. 装载核对与质量核对分开执行：前者证明跑的是哪一版、多少条，后者证明引用、事实与判定字段对得上。
4. 数据文件本体随课程讲次节奏开放，本文只提供清单与口径。
