# 测试方案六件套与要点页

参考课程第 10 讲“方案六件套：目标、指标、场景、数据、环境、验收”中的“六件套清单表”与“方案要点表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 六件套清单表

| 件 | 要明确的内容 | 不明确的后果 | 本项目填写 |
|---|---|---|---|
| 目标 | 基线 b0、容量 c1、稳定性 s1／长稳几类场景，以及具体门禁 | 报告变成“感觉还行” |  |
| 指标 | Goodput、E2E（客户端墙钟）、合格率、错误率；TTFT／TPOT 单列采集 | 拿请求成功率冒充业务合格 |  |
| 场景 | 基准 b0、容量 c1、稳定 s1、异常 e1／e2、恢复 recovery | 只跑容量阶梯，长时间稳定性与恢复全缺 |  |
| 数据 | schema 版本、工单条数、随机种子，三阶段共用 | 跨阶段对比在比数据集差异 |  |
| 环境 | 本机只做冒烟自测、结果不作数；正式结论出自云端隔离环境 | 非正式压测场景被写进容量结论 |  |
| 验收 | 通过、不通过、未验证三类状态；未验证不算通过 | 结论不清，仍报通过 |  |

## 四个压力指标

| 指标 | 含义 | 单位 | 使用边界 |
|---|---|---|---|
| 在线用户数 `U` | 有多少真实用户 | 人 | 需用户行为与到达模型支撑 |
| 平均业务到达率 `λ` | 每秒业务笔数 | 笔/秒 | 示例 `λ≈0.083` 是假设，待业务方校准 |
| 在途业务数 `L` | 同一时刻在途几笔 | 笔 | 与统计窗口绑定 |
| 虚拟用户数 `VU` | 压测机开几个压力线程 | 个 | 只是执行参数，不得直接写成在线用户容量 |

## 方案要点表

| 字段 | 示例写法 | 本项目填写 |
|---|---|---|
| 验证目标 | 三阶段各自在压测环境给出通过／不通过；调优仅最小闭环 |  |
| 非目标 | 真实模型服务商 SLA、前端页面、观测栈自身性能 |  |
| 数据绑定 | MANIFEST 版本／条数／种子；每个窗口记录实际类型分布 |  |
| 环境绑定 | 冒烟＝本机；正式＝四机＋网关＋静默窗口 |  |
| 场景顺序 | 基准 b0 → 容量 c1 → 长时间稳定性 s1 → 异常 e1／e2 → 恢复 recovery |  |
| 验收标准 | 合格率、错误率、E2E P90 阈值；通过／不通过／未验证三态 |  |
| 运行资格 | 缺证据／被干扰／被中止 → NOT_VERIFIED，不据此下结论 |  |

## 判定边界

- 方案不是作文，是下一讲场景表和执行窗口的施工图；写得模糊，后面每一步都得靠猜。
- 三个非目标（真实模型服务商 SLA、前端页面、观测栈自身性能）正式压测阶段不出结论。
- 需求期登记的缺口，方案里不许偷偷修改或抹平。
