# 数据分层与准备检查

参考课程第 10 讲“数据：单一事实源、分层、防失真”中的“工单分层表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 工单分层表

| 分层 | 数量 | 用来考验什么 | 本项目填写 |
|---|---|---|---|
| 标准工单 | 100 条 | 常规配送查询，最基础的数据集 |  |
| 复杂工单 | 40 条 | 多步骤、多工具组合 |  |
| 异常工单 | 30 条 | 依赖返回异常时的降级行为 |  |
| 模糊工单 | 20 条 | 没说清订单号，该澄清而不是硬答 |  |
| 并发工单 | 10 条 | 同用户多会话交织 |  |
| 扩展工单 | 45 条（知识咨询 42、金额核对 2、综合投诉 1） | 知识咨询走知识库检索；金额核对验金额事实；综合投诉带金额＋物流双诉求 |  |

类型之外，再加两个切分维度：查询难度（如 `difficulty` 字段）与依赖返回情况（正常快照、订单不存在、物流异常、需澄清）。类型决定场景构成，难度与依赖返回决定会不会只测到一路绿灯的顺利路径。

## 数据准备三条规矩

1. **生成式，不手改**：工单、订单快照、物流快照由脚本生成，随机种子固定；改需求改生成脚本后重新生成，不直接编辑数据文件。
2. **有版本，有清单**：数据集带 schema 版本号，配 MANIFEST 总清单，写清每个文件多少条、字段含义、哪个阶段消费哪些字段。
3. **跨版本不比较**：数据集版本变化后，读数的分母已变，旧读数不可直接对比。

## 装载核对与质量核对

| 核对 | 回答的问题 | 不过的处置 |
|---|---|---|
| 文件核对 | 数据文件指纹与清单是否对得上 | 不得执行压力场景 |
| 装载核对 | 服务是否真把这套数据装进去 | 不得提前当它装好了 |
| 引用核对 | 工单引用的订单和物流，库里有没有 | 引用对不上不算开跑资格 |
| 事实核对 | `expected_facts` 与快照说的是不是同一件事 | 判定字段对不齐不算开跑资格 |
| 行为核对 | 模糊、异常工单是否按预期行为判定 | 不得当失败洗掉 |

## 输入分布检查

- 每个场景是否记录实际类型／难度／依赖返回构成。
- 是否禁止只抽最容易的标准单刷漂亮曲线。
- 模糊／异常工单是否按 `expected_behavior` 判定，是否剔除。
- 失败业务是否保留进记录，是否为好看洗样本。

## 判定边界

- Mock 同一工单重复跑结果相同，不代表输入分布。
- 装载核对只证明跑的是哪一版、多少条，不证明数据质量过关。
- 引用断了或判定字段对不齐，压测流量就落不到该压的路径上，合格率不可信。
