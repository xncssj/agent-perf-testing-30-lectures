# 环境清单、版本指纹与执行顺序

参考课程第 10 讲“环境：能复现是底线，隔离是红线”“版本指纹：给每一轮数据发一张‘身份证’”“执行顺序与运行资格”中的“环境口径表”“版本指纹表”“执行顺序表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 环境口径表

| 口径 | 用途 | 结论能不能对外 | 本项目填写 |
|---|---|---|---|
| 本机自托管（服务 + 本地库 + Mock） | 开发冒烟、脚本自测 | 不能当验收容量 |  |
| 云端四机隔离压测环境 | 正式压测窗口取证 | 可以出压测环境结论，仍标 Mock／链路前提 |  |

## 四机角色

| 机器 | 角色 | 必须登记 |
|---|---|---|
| `pt-control` | 发压与取证 | 规格、发压工具版本、是否与网关共驻 |
| `sut-agent` | 被测系统 | 规格、阶段、端口、服务指纹 |
| `dep-services` | 工单、订单、物流、数据库等依赖 | 规格、依赖版本、连接方式 |
| `obs-stack` | 观测监控平台 | 规格、采集项、自耗是否另账 |

隔离红线：正式压测窗口统计期间禁止并行部署；禁止经控制 EIP 做维护 SSH；同机冒烟要承认压测与被测互相抢资源；密钥只经环境变量注入，绝不写进入库文件。

## 环境清单最少六样

1. 四台机器各自的角色和规格。
2. 被测服务跑在哪个端口。
3. 网关开没开、走哪条链路。
4. 观测开没开、哪些读数被污染。
5. 数据集装没装好、文件与装载是否核对过。
6. 一条触发就立即停压的暂停线。

## 暂停线

| # | 暂停线 |
|---|---|
| 1 | 错误率连续 2 分钟超过 5% |
| 2 | 合格率较同台阶基线掉超过 5 个百分点 |
| 3 | 服务端非正常终态计数持续上涨 |
| 4 | 单位时间 Token 消耗超过同台阶基线 2 倍 |
| 5 | 环境被变更（依赖升级、数据集重生成、他人同机作业） |

## 版本指纹表

| 指纹项 | 权威来源 | 本项目填写 |
|---|---|---|
| 数据 schema／条数／种子 | MANIFEST |  |
| 代码 | `git rev-parse HEAD` ＋分发归档包哈希 |  |
| 模型、Prompt、工具与流式 | 模型提供方开关、流式开关、Mock 时延参数、Prompt／工具版本哈希 |  |
| 依赖与业务接口 | 依赖清单、订单／物流快照版本、API 契约版本 |  |
| 服务指纹 | 服务自报 `/version` 返回的文件哈希与 SLO 门槛 |  |
| 运行身份 | Task ID、Run ID、Trace ID、场景、阶段、时间窗 |  |

**版本号相同仍需核对指纹；指纹不同还要追查具体配置。** 界面“当前选用”不能替代实际运行指纹，要分别记录配置列表、界面选用状态与当轮启动配置、服务指纹。

## 执行顺序表

| 次序 | 动作 | 为什么在这个位置 |
|---|---|---|
| 1 | 判定逻辑自测 | 先证明判对判错的逻辑本身是对的 |
| 2 | b0 基准（冷启动、热启动分开跑） | 固定条件先跑一轮打底，当后面所有对比的原点 |
| 3 | 流式基准 | 补齐用户体验口径 |
| 4 | c1 容量阶梯 | 逐级加压找拐点，阶梯中途不回退重跑 |
| 5 | s1 长时间稳定性 | 看时间维度上的退化 |
| 6 | 异常与恢复场景 | 最依赖前面结论的放最后 |
| 7 | 更新实验记录、出报告 | 证据落实了之后才算完 |

## 判定边界

- 能复现是底线：任何人、任何时候按同样步骤跑，同样输入应得到对得上的数据。
- 隔离是红线：压测流量绝对不能触达生产系统。
- 切换业务链路（进程内直读 ↔ HTTP 调 Java 服务）等于换系统，必须重跑基线。
- 中途被中止、样本不够、环境被干扰的轮次一律 NOT_VERIFIED，产物保留但不进容量曲线。
