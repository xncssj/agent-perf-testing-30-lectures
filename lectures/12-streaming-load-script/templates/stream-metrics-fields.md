# 流式三时刻、采集字段与读数指引

参考课程第 12 讲“TTFT：哪个瞬间才算「第一个字到了」”“TPOT：片段到了，不等于就有有效结果了”“一笔业务，到底记哪些字段”中的“流式三时刻表”“采集字段表”“读数指引表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 流式三时刻表

| 时刻 | 是什么 | 脚本怎么处理 |
|---|---|---|
| 首字节 | 响应头后第一个网络字节到达 | 不单独计时：从请求发出起计，建连与首字节拆不出来，不装能拆 |
| 首 Token | 首个有效答复片段到达 | 客户端实测，字段 `ttft_client_sse_ms` |
| 首个有效内容 | 用户看着“像答复”的内容 | 是否算有效由体验目标事先约定；脚本只保证空块和心跳不冒充 |

## 三条流式规则

1. **心跳不充当首 Token**：`: keepalive` 行直接忽略，不进任何时延样本。
2. **空块不充当首 Token，也不悄悄丢**：过滤数量单列在 `empty_filtered`。
3. **空白字符是正文**：判定有效内容时不做去空格处理，否则答复原文与 Token 边界一起被破坏。

## 采集字段表

| 分组 | 字段 | 口径注意 | 能否进门禁 |
|---|---|---|---|
| 身份 | `task_id`、`batch_id`、`run_id` | 业务标识即工单号；运行标识由服务端每次运行生成 | 资格前提，缺了整轮不算数 |
| 终态 | `status`、`stop_reason`、`stream_status` | 优先认服务端终态，不拿 HTTP 200 推断流程成功；预算耗尽不算流程完成 | 进判定 |
| 时延 | `e2e_ms`、`ttft_client_sse_ms`、`tpot_ms` | E2E 是客户端墙钟（k6 契约里叫 `e2e_client_wall_ms`），门禁只认它；TPOT 单位随 `tpot_unit` | E2E 能进；TTFT、TPOT 候选 |
| 节奏参考 | `char_intervals_ms` | 只能作流式节奏校准，不得读作 TPOT | 不能 |
| 用量 | `total_tokens`、`usage_source` | 来源分服务商上报、估算、缺失、混合；Mock 口径全是估算 | 观测与成本候选 |
| 证据 | `evidence_kind` | 真实流式还是回放；回放只用于采集器计时校准 | 回放不能进基线 |
| 质量 | 关键词、事实、行为三类命中明细 | 判定依据全部记下，不只留一个合格率 | 进判定 |
| 轨迹 | 事件类型序列、中断状态 | 服务端指标整包另存，不覆盖客户端墙钟 | 不能，留作 RESAR 对照 |
| 指纹 | 模型服务商、流式模式、数据版本、代码提交号 | 经 `/version` 与当轮记录核对 | 资格条件，缺指纹这轮不算数 |

## 样本批次表

| 样本批次 | 采集口径 | 读法 |
|---|---|---|
| 早期流式轮 | 片段按字符逐个产出 | 间隔只能读作字符节奏 |
| Token 边界重采 | 按确定性 Token 边界重切 | 同一批工单换口径重采，不是换算 |
| 非流式对照 | 旧版“计算口径”，已废弃 | 仅作反面教材，禁止与实测同表 |

## 读数指引表

| 想回答的问题 | 优先看的字段 | 常见误读 |
|---|---|---|
| 用户多久看到有效内容 | `ttft_client_sse_ms` | 拿首字节或客套话片段当 TTFT |
| 出字是否卡顿 | `tpot_ms` 与逐 Token 间隔序列 | 拿 `char_intervals_ms` 当 TPOT |
| 业务是否合格 | 终态加判定结果 | 只看 HTTP 200 |
| 中断路径通不通 | 中断状态与中断时刻 | 把中断失败混进业务失败里报 |

## 判定边界

- 片段不等于 Token：真实模型下这套重切规则恢复不了 Token 边界，拿不到端点返回就只能留片段级口径。
- 只输出一个 Token 时 TPOT 不适用，记 `None`，不填 0。
- 拿非流式 E2E 除以输出 Token 数只是定位线索，不能进 SLO 卡片或门禁。
- 每条时延数字交付前过三问：哪一层？从哪算到哪？能否代表用户等待？
