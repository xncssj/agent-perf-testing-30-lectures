# 采集线路与场景映射

参考课程第 12 讲“先分家：k6 跑业务，Python 看流式”中的“采集线路表”与“场景采集表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 采集线路表

| 线路 | 工具与接口 | 采什么 | 不采什么 |
|---|---|---|---|
| 业务线 | k6，打非流式接口 | 端到端业务时延（客户端墙钟）、四级判定、Goodput、错误率 | 真实 TTFT、TPOT |
| 流式线 | Python `stream_benchmark.py`，打流式接口 | 客户端 TTFT、TPOT、逐事件轨迹、中断终态 | 高并发容量压力 |

两条线各自采样、各自计算：流式小样本、k6 压力场景数值、历史 Python 容量读数，三笔账单位和环境都不同，不能写进同一句容量结论。

## 脚本入口清单

| 线路 | 入口 | 负责什么 |
|---|---|---|
| k6 场景 | 基准、容量、稳定性、异常、多轮五类场景脚本 | 非流式业务压力、四级判定、Goodput 与成本字段 |
| Python 执行 | `benchmark.py`、`capacity.py`、`stability.py`、`stream_benchmark.py` | 单笔基准、容量阶梯、长时间稳定性、流式采集 |
| 共享核心 | `common.py` | 四级判定与聚合；判定口径只保留一份 |
| 双线自测 | 判定自测脚本 | 改判定后先跑自测，再进正式轮次 |

## 场景采集表

| 场景 | 主采集线路 | 要单独说明的点 |
|---|---|---|
| b0 业务基准 | k6 非流式接口 | 冷启动与热启动分开跑，预热段不进计量 |
| B0s 流式基准 | Python 流式脚本 | TTFT、TPOT、中断终态，样本短而可追踪；单独运行标识，不塞进 c1 |
| c1 容量 | k6 非流式接口 | 每级各出一份摘要；架构升级阶段服务端首字要过门禁 |
| s1 长时间稳定性 | k6 非流式接口 | 按早、中、后分段看衰退；缩短版必须声明 |
| e1 spike | k6 非流式接口，流量模式选突发 | 与骤降共用脚本，按模式参数分开跑、各记运行标识；逐段摘要，判定以整轮为单位 |
| e1 drop | k6 非流式接口，流量模式选骤降 | 与突发对称、可对照读；判定同样以整轮为单位 |
| e2 多轮会话 | k6 配套脚本 | 逐轮阈值核对进摘要，三态判定以整轮为单位 |
| recovery | 阶段一无脚本（登记待补） | 无注入开关时按缺口处理，不空跑冒充 |
| 流式中断 | Python 流式脚本（中断参数） | 中断状态与业务失败分开统计 |

## 使用检查

1. 该用流式压测的场景，不许让 k6 非流式“估”一个 TTFT。
2. 每个场景的运行标识、数据版本、采集线路在结果文件里能对上。
3. 映射表贴进脚本交付列表，执行环节逐行打勾。

## 判定边界

- 业务线和流式线可以同环境，但结论不能拼成一次容量结论。
- 回放数据只用于采集器计时校准，不能进基线。
- 缺注入开关的恢复场景登记缺口，不拿旧口径重启读数冒充。
