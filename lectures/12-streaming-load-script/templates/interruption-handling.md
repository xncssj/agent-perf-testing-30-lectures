# 断流处理与脚本自证

参考课程第 12 讲“流会断：断出来的样本也是证据”“脚本先自证清白，再执行压测场景”中的“断流处理表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 断流处理表

| 断法 | 终态标记 | 脚本的动作 |
|---|---|---|
| 服务端断流（流结束了，结束事件没到） | `truncated` | E2E 退回按“请求发出到流结束”的墙钟计；判定退回“只看最终答复文本”的口径 |
| 客户端主动断（`--abort-after N`） | `client_aborted` | 第一笔业务收到第 N 个有效片段后断开，验证服务端对断开的处理 |
| HTTP 状态非 200 | 记失败业务 | 写明状态码，四级判定全不通过 |
| 超时或其他异常 | 记失败业务 | 写明异常类型，继续下一笔 |

## 断流留证检查

| 检查项 | 期望 | 当前状态 |
|---|---|---|
| 流内每种断法有明确终态标记 | truncated／client_aborted／失败业务 |  |
| 已收到片段一笔不丢 | 断流后仍保留片段与时刻 | 请求层失败当前只记错误类型，待修 |
| 失败耗时单独记录 | 保留已采片段，时延位置记空 | 当前超时、连接异常时延写死 0，待修 |
| 中断样本单独统计 | 不混进完整合格统计 | 中断样本文本命中要点仍可能计入合格，待补 |
| 安全维度进判定 | 护栏结果被判定器消费 | 流式结果文件当前记空，待补 |

## 脚本自证顺序

1. 判定逻辑自测：不过，后面一律不开跑。
2. 流式线小样本：采 TTFT／TPOT，再验一次客户端主动中断。
3. k6 侧判定自测与非流式冒烟：正式轮走受控入口，不与冒烟混着报。

## 判定边界

- 断流不是小概率事件；脚本的目标不是保证不断，而是断得明白、留得住证据。
- 请求层失败把时延填 0 会拉低 P90，必须修正为“保留片段、失败耗时单列、时延记空”。
- 中断、截断没有服务端终态时，只能回退文本口径；这类样本另算，不能混进完整合格统计。
- 回放模式（`STREAM_MODE`）用于校准采集器计时，不能进基线。
