# 第 12 讲配套资料

本讲主题：流式 Agent 的压测脚本怎样采集 TTFT、TPOT、轨迹和业务结果？

本目录提供 3 份模板，对应正文中的采集线路表、场景采集表、流式三时刻表、样本批次表、断流处理表、采集字段表与读数指引表。本目录不包含正文图片、项目源码或逐笔原始数据。

## 模板

| 模板 | 用途 |
|---|---|
| [采集线路与场景映射](templates/dual-line-collection.md) | 业务线 k6 与流式线 Python 分工，八个场景各走哪条线路 |
| [流式三时刻、采集字段与读数指引](templates/stream-metrics-fields.md) | 首字节／首 Token／首个有效内容的边界，九组字段能否进门禁，三批样本与防误读 |
| [断流处理与脚本自证](templates/interruption-handling.md) | 四类断流的终态标记、留证缺口与“先自证再开跑”的顺序 |

## 使用方式与证据状态

1. 业务线与流式线分开采样、分开计算；三笔账（流式小样本、k6 压力、历史容量）不并列比较。
2. TTFT 的起点是客户端业务请求，终点是首个有效答复片段；与模型调用层的口径不能直接互比。
3. TPOT 的 Token 边界在 Mock 口径下可靠；真实模型拿不到端点内容时只留片段级口径。
4. 缺失与不适用一律记 `None`，不填 0；`char_intervals_ms` 不得读作 TPOT。
5. 断流、中断、请求层失败的留证缺口如实登记，不把修复前的读数当完整证据。
