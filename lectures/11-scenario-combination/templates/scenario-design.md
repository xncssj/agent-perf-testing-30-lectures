# 基准、容量、稳定性与异常设计表

参考课程第 11 讲“基准：先把基线跑明白”“容量：看它在哪一级开始衰减”“稳定性：两分钟跑不出一个夜晚”“异常：主动抖一下，看它怎么收场”“多轮会话：用户会追问，上下文会膨胀”中的五张设计表。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 基准设计表

| 要素 | 定成什么样 | 为什么这么定 | 本项目填写 |
|---|---|---|---|
| 输入 | fixed 固定集池内轮换，增加 VU 覆盖全部底层工单 | 只循环几条，Mock 确定性会让基线是同一个结果 |  |
| 压力 | 先预热再正式统计；冷启动、热启动分开各跑一轮、各记 Run ID | 冷启动要重启服务、不预热，不能与普通基准合并 |  |
| 观测 | 压测端合格率、时延分位、Goodput、Token 与成本；服务端 `/metrics`、日志 ERROR；四张看板 | 基准还要回答“多贵” |  |
| 停止条件 | 五条暂停线，任一触发即暂停、保留现场 | 该停还硬压，压出来的只有残骸数据 |  |
| 验收阈值 | 三态门禁：合格率、错误率、墙钟 E2E P90；真实模型轮按校准窗重定 | 压线算达标；证据缺一即 NOT_VERIFIED |  |

## 容量设计表

| 要素 | 定成什么样 | 为什么这么定 | 本项目填写 |
|---|---|---|---|
| 输入 | load 数据池，六级台阶共用同一个池、同一份数据文件（同哈希），池内轮换 | 同池同哈希是级间可比的前提 |  |
| 压力 | 连续递增阶梯；每级站稳 1 分钟 + 计量 2 分钟，站稳段不入分母 | 逐级加压，阶梯中途不许断开重跑 |  |
| 观测 | 双路监控另加台阶切换时的业务读数；链路依赖层两张看板 | 上一级尾延迟会拖进下一级 |  |
| 停止条件 | 五条暂停线，外加压测机容量预检 | VU 预分配超过压测机能力会先压死压测机 |  |
| 验收阈值 | 三态门禁逐级判定；只引用每级自己的摘要 | 跨级统计会把衰减抹平 |  |

退化记两个值：首个 SLO 不达标的台阶、开始衰减的台阶。

## 稳定性设计表

| 要素 | 定成什么样 | 为什么这么定 | 本项目填写 |
|---|---|---|---|
| 输入 | 与 b0 同池，池内轮换 | 与基准同输入才可比 |  |
| 压力 | 固定 VU；正式时长 = 运维周期内业务总量 ÷ 选定 Goodput，待业务方校准 | 按墙钟触发的风险（如 8 小时会话超时）另算真实时长 |  |
| 观测 | 整轮三等分看平均时延走势；首、末两个完整 5 分钟桶的有效吞吐量对比 | 两个口径分开报 |  |
| 停止条件 | 五条暂停线 | 最怕悄悄衰减 |  |
| 验收阈值 | 三态门禁 + 末段性能衰退阈值；缩短版只观测 | 2 分钟答不了“跑一晚上稳不稳” |  |

## 异常设计表

| 要素 | 定成什么样 | 为什么这么定 | 本项目填写 |
|---|---|---|---|
| 输入 | 与 c1 共用同一个池、同一份数据文件 | 骤降与突发逐段可比的前提 |  |
| 压力 | spike 分三段（低 → 高 → 低），drop 对称两段；各记各的 Run ID | 突发与骤降是高峰的两面 |  |
| 观测 | 注入与恢复时刻、影响面、恢复时长逐项记录 | 不记时刻和时长等于白抖 |  |
| 停止条件 | 五条暂停线 | 异常轮最容易把循环和重试打爆 |  |
| 验收阈值 | 分段核对合格率与时延阈值；三态判定以整个场景为单位 | 突发段合格、回落段不合格，整体判 PASS 就全错了 |  |

## 多轮设计表

| 要素 | 定成什么样 | 为什么这么定 | 本项目填写 |
|---|---|---|---|
| 输入 | 连续多轮请求，每轮叠入轮次标注与递增填充文本 | 当前实现是递增输入模拟，各轮独立取工单 |  |
| 压力 | 轮间隔、每轮上下文增量 | 统计时段要长过监控采样间隔 |  |
| 观测 | 轮次、请求体大小、逐轮合格率；服务端真实上下文占用交给业务监控 | 客户端只能构造上下文长大的间接证据 |  |
| 停止条件 | 五条暂停线 | 上下文滚大最容易触发 Token 成本暂停线 |  |
| 验收阈值 | 分轮核对合格率与时延；三态判定以整轮为单位 | 第 5 轮衰减比第 1 轮更有价值 |  |

## 判定边界

- VU 是压测单位，不是在线用户数；容量结论用脚本口径的有效吞吐量承载。
- Mock 模型场景的时延不代表真实模型；两套口径不并排比较。
- 缩短版、未跑项、旧链路读数必须在状态列写明，不能假装已验收。
