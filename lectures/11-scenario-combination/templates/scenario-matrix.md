# 场景矩阵

参考课程第 11 讲“先把每一类场景对到一个业务风险上”“汇总表：本讲交付物落在一张纸上”中的“场景动机表”与“场景总表”。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 场景动机表

| 场景 | 需要回答的业务问题 | 答不出来的后果 |
|---|---|---|
| 基准 b0 | 这笔业务到底多快、多贵 | 成本算不清、SLO 拍脑袋，后面每级对比没有锚 |
| 容量 c1 | 高峰会不会垮，垮之前先坏什么 | 促销当场出事，而且不知道先坏的是哪一层 |
| 稳定性 s1 | 跑一晚上还稳不稳 | 半夜悄悄退化，早上业务暴雷 |
| 异常 e1/recovery | 有压力时抖一下异常，Agent 是自愈还是把工单搞错 | 小故障扩大化，答非所问还发现不了 |
| 多轮 e2 | 用户追问、上下文累积后，时延、合格率与成本会不会变差 | 拿单轮结果外推多轮，轮次一多就失真 |

组合顺序：**基准先立尺子 → 容量找拐点 → 稳定看衰退 → 异常看扩散与恢复 → 多轮看上下文累积**。跳过基准直接上容量，性能衰减时都不知道跟什么对比。

## 场景五要素

每张场景表都要写清：输入、压力、观测、停止条件、验收阈值。

| 要素 | 要写什么 | 常见缺口 |
|---|---|---|
| 输入 | 数据池、轮换方式、覆盖要求 | 只循环几条工单，确定性让基线变成同一个结果 |
| 压力 | VU／压力线程、阶梯、预热与计量分段 | 把 VU 写成在线用户数 |
| 观测 | 压测端业务读数、服务端与宿主环境指标、看板 | 只看单路，服务端与压测端口径混读 |
| 停止条件 | 五条暂停线、压测机容量预检 | 缺停止条件，执行到服务爆炸才行 |
| 验收阈值 | 三态门禁、逐场景判据 | 缺验收阈值，跑完没法判 |

## 判定边界

- 组合完整不等于每项都已正式验收；缩短版、旧链路环境、未测项必须在状态列明确写出。
- 场景表是风险对赌清单，不是压力参数表；先写业务风险，再填压力。
- 零样本阶梯必须清楚标“样本不足”，不得静默当通过；被中止的轮次一律 NOT_VERIFIED。
