# 案例一实验数据（Single Agent 客服工单系统）

> 本文件收录《Agent 性能测试实战30讲》第 03 讲引用的客服工单系统 Single Agent 阶段（案例 1）实测数据，提供实验配置与汇总统计，不包含逐笔原始数据。
> 运行口径：Mock 模拟模型（`LLM_PROVIDER=mock`、`seed=42`），按字符逐个输出，文中字符数与真实模型的分词计数并不对应；单价为 Mock 假设（2 元/千 token，仅演示成本口径）。

## 2. 非流式基准（50 样本）

| 指标 | Mean | P50 | P90 | P99 | Min | Max |
|---|---|---|---|---|---|---|
| E2E (ms) | 2266.2 | 2330.0 | 2552.8 | 2670.7 | 1587.4 | 2729.1 |
| TTFT (ms，合成) | 2876.4 | 2919.4 | 3175.3 | 3369.0 | 2121.6 | 3413.6 |

- 合格业务 50/50 = 100%；E2E P90 2552.8ms（约 2.55 秒），计时止点为引擎内部执行结束。
- 非流式接口的 TTFT/TPOT 为合成口径（决策耗时 + 配置 token 间隔），仅作对照，不是客户端实测值。

| 指标 | Mean | P50 | P90 | P99 | Min | Max |
|---|---|---|---|---|---|---|
| TTFT (ms) | 2250.4 | 2294.8 | 2472.6 | 2547.9 | 1738.5 | 2558.5 |
| E2E (ms) | 4547.6 | 4614.0 | 4788.4 | 4836.6 | 4018.4 | 4839.8 |
| 相邻字符事件间隔 (ms) | 40.7 | 40.7 | 40.8 | 40.8 | 40.7 | 40.8 |

- 历史脚本登记合格 20/20 = 100%；E2E P90 4788.4ms（约 4.79 秒），计时止点为客户端实测到流式输出收尾；TTFT 与 E2E 为该批次客户端实测值。
- 表中「相邻字符事件间隔」是 Mock 逐字符产出的字符事件间隔，只能作流式节奏校准，不是 TPOT。

## 4. T00001 服务端事件时序

一笔工单（T00001）的服务端事件按相对请求开始的时刻排开：

| 时刻 | 事件 |
|---|---|
| 0.017ms | `thinking`（服务端发出处理提示） |
| 658ms | `tool_call`／`tool_result`：query_order 工具执行完成 |
| 1301ms | `tool_call`／`tool_result`：query_logistics 工具执行完成 |
| 2498ms | 首 `answer`（首个答复 Token） |

- 该记录包含 3 次规划调用，是跟随决策结果发生的实际循环，循环只设上限，不是预先安排的 3 轮。首个答复前还包含工具执行、答复准备及生成等待。
- 表中是相对请求开始记录到的事件时刻，不是各次调用的持续时间；模型累计时间须将各次调用的持续时间逐笔相加，不能相加事件时刻。
- 4.79 秒来自同阶段 20 笔客户端流式样本的 P90，与这 4 个单笔服务端事件不是同一批样本，不能拼成单笔时间线或相减反推等待。

## 5. 来源与证据边界

事件时间轴及计时边界见课程第 03 讲“三种时间不能直接做减法”中的“事件时间轴表”；字符与词元粒度的区别见课程第 04、05 讲。

历史“合格”是该批次原脚本的登记结果。本文件未提供逐笔质量、时延和安全交集证据，不能用 50/50 或 20/20 直接填入当前第 04 讲口径的 Q。非流式 TTFT 为合成口径，历史字符间隔只作输出节奏校准，均不当作真实模型 TPOT。

本记录不包含逐笔原始数据。客户端时间、服务端时间、字符粒度历史批次和后续词元边界批次须分别记录。
