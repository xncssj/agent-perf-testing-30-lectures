## 1. 本次核实的事实

1. 云上标准 `lab.sh run` 默认注入 `GATEWAY_URL=https://<IP>`。业务请求经控制机同机私网 HTTPS 回环、统一 Nginx 网关鉴权、阶段前端 Nginx 的 `/api/` 代理到 Agent；k6 不执行浏览器页面渲染。
2. `BASE_URL` 与 `manifest.target.base_url` 保留 Agent 地址，供 `/health`、`/version` 与 `/metrics` 直连采样。业务请求是否使用它，由 `runtime.gateway.enabled` 的选择分支决定；不能据此单字段判断业务直压。
3. 阶段 1 当前根 Compose 注入 `JAVA_SERVICE_ENABLED=true`，`AgentService` 注册 Java 订单、物流工具，数据由 Java 查询 MySQL `order_logistics`。知识工具仍读取 Agent 数据后端，云上为 MySQL `cs_agent`；阶段 2/3 仍使用各自的 SQLite 或进程内数据与 RAG 实现。
4. 网关业务链路的客户端 E2E 包含网关与阶段前端代理。k6 与网关共驻 `pt-control`，即使 k6 与 Agent 分机，也须核对控制机资源竞争。`GATEWAY=0` 直连对照与网关口径分别标注。
5. 标准编排仅暂停非目标阶段并对其前缀返回 503，目标阶段继续可测。替代运行器是否真正隔离，应读取当窗记录；前述设计不证明预压测第三轮已执行标准隔离。

代码依据：发压编排、业务 URL 选择、阶段路径拼接、网关前端上游、前端 API 代理、Compose 端口与开关、阶段 1 工具注册。

## 3. 撤销的架构前提与分析影响

| 原表述 | 本次处理 | 后续分析要求 |
|---|---|---|
| `target.base_url` 指向 Agent，所以业务不经网关，前端也不在链路 | 撤销该推断。预压测第三轮原始业务 URL 与网关指纹已证明经网关及前端代理 | 客户端与服务端时间差必须保留网关、前端代理及网络等候选区域，不能只归因 Agent 入口 |
| Java 不在阶段 1 工具链路，JVM 只作阴性对照 | 预压测第三轮该排除条件无效，`java_service_enabled=true` 与注册分支一致 | Java 接口、连接池和 MySQL 属于按需订单、物流路径；是否异常仍须同期指标或 Trace，不能由路径存在推断瓶颈 |
| 分机发压足以证明施压自耗不影响被测路径 | 撤销该充分性判断，网关与 k6 共驻控制机 | 将控制机水位与网关日志纳入同窗核对；没有数据时登记未排除项 |
| 压测时整座网关置为 503 | 修正为标准编排只暂停非目标阶段前缀 | 对实际采用的运行器核对容器与隔离标记，不能把设计状态当实测状态 |

受影响资料：

- 预压测第二轮 S2 底稿及同名 JSON、S4 底稿及同名 JSON、第二轮报告草稿。其“仅凭 base_url 确认不经网关”的依据不足；本次未取得该轮原始业务 URL 与 Java 指纹核对，历史实际路径标为待复核，不能用第三轮事实倒填第二轮。
- 预压测第三轮 S2 底稿及同名 JSON、S4 底稿及同名 JSON。其直压、排除 Java、施压自耗充分性判断按上表撤销；原始时点和测量值保留。
- 两轮下游 S3—S7 中依赖这些架构排除条件的时间归因、阴性对照或机制排除须重新审阅；本次不自动改写瓶颈判定、受染评级、门禁结果或验收状态。

上述底稿及报告的原判读保留作为历史记录；涉及被撤销前提的 Markdown、JSON 字段不得继续作为架构事实输入。部署正文、架构底图、运行说明及分析手册已同步当前口径，报告入口附加本勘误提示。后续重审须逐窗补足原始业务 URL、版本指纹、同期网关与 Java 证据，再形成修订底稿。
