# 候选节点九项检查与优先级

参考课程第 15 讲“候选节点怎么圈”中的九类候选节点检查与优先级规则。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 走一笔业务的五个问题

沿“意图 → 决策循环 → 查订单／查物流（经 Java 服务）→ 结果回填 → 再决策 → 生成答复”的每个箭头问：

1. 这里会不会串行等待？
2. 会不会重试放大？
3. 会不会和别的并发抢同一条连接？
4. 会不会被观测上报拖住？
5. 压力升上去，会不会堵在网关、前端、入口接收之前？

哪一步答了“会”，哪一步才有资格进候选表；五个问题全答“不会”还硬涂红，等于把瞎猜当分析。

## 九类候选节点检查

| # | 候选节点 | 要核什么 | 本轮状态 |
|---|---|---|---|
| 1 | 决策循环 | 轮次上限、循环退出、预算耗尽 |  |
| 2 | 模型推理调用链 | 首字与整笔时延、尾部时延、服务商侧与代理等待是否拆开 |  |
| 3 | 工具串行等待 | 订单查完再查物流的墙钟叠层 |  |
| 4 | Java 订单物流服务 | 是否真在被测路径上；别与知识库混为一谈 |  |
| 5 | 数据库与共享连接 | 并发是否抢同一条连接 |  |
| 6 | 工具池 | 线程数、队列长度、满了是排队还是快速失败 |  |
| 7 | 统一网关与前端代理 | 加密、鉴权、转发增量 |  |
| 8 | 控制机共驻 | 网关、发压工具、出网代理是否同机抢资源 |  |
| 9 | 观测上报 | 是否从被测进程发出、自耗多少、是否关闭 |  |

## 优先级

| 优先级 | 范围 | 处理 |
|---|---|---|
| 第一 | 本轮瓶颈可疑点直接命中的节点 | 优先取证，模型推理调用链与服务商侧 |
| 第二 | 压测架构上会放大时延或 Token 的节点 | 工具链串行、出网代理、Java 与数据库；已修复的共享连接事故留此提醒回看 |
| 第三 | 只涉及自耗与观测干扰的节点 | 标识为自耗干扰，不记成被测容量不足 |

## 判定边界

- 候选节点表是嫌疑清单，不是判决书；风险显不显形很看环境。
- 红点不是越多越好；太多等于没有重点，用优先级分。
- 已修复的问题不要再写成当轮瓶颈。
- 前端工作台不在本课压测范围，页面时延不许混进 Agent 容量结论。
- 没有拆开服务商侧与代理等待的调用链读数，不能单独证明瓶颈。
