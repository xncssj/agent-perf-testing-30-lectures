# 单笔业务复核记录

来源：课程第 01 讲“四级判定表”“逐笔复核表”及业务标识、运行标识的关联说明。先确认各处证据来自同一次运行，再分别记录各层状态。

## 填写区

| 字段 | 填写内容 |
|---|---|
| 业务标识（Task ID） | |
| 运行标识（Run ID） | |
| 业务输入、目标与约定交付边界 | |
| 判据、数据与报告版本 | |
| 请求标识、轨迹标识、步骤与交付物关联 | |
| 请求层状态与证据 | |
| 流程层状态与证据 | |
| 业务层状态与证据 | |
| 验收层状态与证据 | |
| 质量、时延、安全、成本各项状态与证据 | |
| 失败、超时、取消或未验证的终态与原因 | |
| 抽样规则、样本量与覆盖范围 | |
| 待补证据 | |
| 复核人 / 复核时间 | |

状态使用“通过／失败／未验证／不适用”，不适用需说明依据。请求重试、异步查询可能产生多个请求标识，不能假设 1 个请求标识贯穿整笔业务；记录其与同一运行的映射。

## 填写示例

| 字段 | 示意填写 |
|---|---|
| 业务标识／运行标识 | 示意工单 A／示意运行 A-1 |
| 请求层 | 通过：200 且响应结构符合约定 |
| 流程层 | 通过：必要步骤、回复交付与结束记录齐全 |
| 业务层 | 未验证：有回复，缺物流核对与评测结果 |
| 验收层 | 未验证：质量、时延、安全与成本证据不齐 |
| 待补证据 | 订单物流快照、答复评测、业务时间戳、安全检查记录及成本明细 |
| 证据状态 | 纯示意，不代表实际运行结果 |

该示例只能确认请求与流程层。补齐证据后更新业务和验收结论，保留复核时间及变更记录。汇总时单列未验证数量，不能删除这类业务来提高成功率。
