## 二、假设验证更新（对照 S2 映射逐条收敛）

### H2「SUT 施压路径未饱和」——**资源侧成立**

- 50VU 档被测容器仅 **0.326 核均值**（4 核机 8%）、整机 0.36 核；L5→L50 容器 CPU 0.033→0.326（VU ×10，CPU ×10 **线性**，无饱和拐点）——与 S1「Goodput 线性 + P90 平坦」互为印证：**容量约束不在 SUT 资源**。
- 内存观察项：被测容器约 52MB（空窗基线 11:55—12:00Z，复算 51.6MB）→ stab 三段 69.4→74.9→77.1MB，**段间增量递减（5.5→2.2MB/10min 段，收敛形态）**——warmed-up 缓升而非无界泄漏；30min 窗内无泄漏证据，长稳结束后数分钟工作集即回落至 ≈52MB（非泄漏旁证），小时级长窗复测时可复查斜率（与 Mock 轮内存平稳形态的差异来自真实轮更大的响应体与对象量，登记观察项 O-MEM）。
> **2026-10-17 内存读数勘误**：本段原值 49MB／68.6→72.2→74.3MB（增量 3.4→2.7→2.1）系聚合件窗偏差旧值，已按原始工作集序列（正确窗、三段＝12:40 起每 10 分钟）复算更正；「逐段增量递减、缓升非泄漏」定性不变。

### H3「高档位 P90 +13—20% 排队落点」——**本侧已采指标未见资源饱和（等待类机制不在此列），落点收敛到 LLM 往返链**

- 高档位（L50）两机 CPU 均 <0.36 核（各 4 核机 9%）；被测容器 CPU 随 VU 线性。等待型排队不耗 CPU——低占用排除不了工具排队、连接与查询等待（U6），不据「无排队资源形态」下排除结论。
- Java/MySQL（dep 机）全场 **≤0.01 核**——工具的 DB 侧处理器开销可忽略；慢查与连接等待低占用排除不了，待 S5 span 终验。
- pt-control（k6+网关+tinyproxy 共驻）L50 时 0.32 核、load1 max 0.87——远未饱和；S3 实测差值段稳态 P50≈5—6ms/P90≈7ms，**只支撑入口跳候选按稳态量级降级、不升级为排除（起跑/换档簇成因未验、GATEWAY=0 直连对照未执行——D3 挂账；e1 两窗不剔簇 P90 506.8/534.5ms 落在起跑簇）；tinyproxy 代理自身的等待在服务端耗时内部、差值段测不到，保留待验证（2026-10-19 边界注）；H3 落点收敛为「DeepSeek API 并发排队」主候选 + 「LLM 决策调用链串行性」结构项**（最终判别靠 S5 span 分解 + S6 评审；外部侧黑盒按阴性排除法）。

### H7「stab 桶 6 时延抬升系外部波动」——**阴性排除法闭环，显著加强**
