# 无法归因清单与成本分母

参考课程第 16 讲“Token 与成本同步拆”“拆不出来的，标「无法归因」”中的成本核对与缺口交接。使用说明见[本讲说明](../README.md#使用方式与证据状态)。

## 无法归因清单

| 编号 | 缺什么 | 受影响的结论 | 从哪里补 | 当前状态 |
|---|---|---|---|---|
| A1 | 工具次数梯度里决策往返与工具执行各占多少 | 不能判断“多一个工具固定加几秒” | 第 18 讲逐笔分解 | 待补 |
| A2 | 差值段内部五样各占多少 | 不能升级为“网关可以忽略” | 绕开网关的直连对照 | 待补 |
| A3 | 最后一次决策到首个答复片段之间约 6.7s 空段 | 不能写成“模型先想后吐字” | 服务端打点与 span | 待补 |
| A4 | 慢尾/流式调度盲区 | 不能把阶段三盲区并进本轮 | 阶段三独立取证 | 本轮不适用／待补 |

每条写清：缺什么、影响哪个结论、从哪补、现在什么状态。编一个原因，会在瓶颈判定那一步变成冤案。

## 成本核对三看

| 核对 | 错误做法 | 正确做法 |
|---|---|---|
| 看分母 | 全轮 Token 除以计量窗业务数，单笔虚高约五成（示例 5601 对 3627.7） | 分子分母同源；全轮 Token 对全轮业务数 |
| 看覆盖 | 用量缺失时用总量硬算平均 | 缺失按缺失处理，另报覆盖率 |
| 看同源 | 把“慢”和“贵”当同一个原因 | 慢在首字节前 LLM 往返链；贵在每笔固定检索与生成开销；减少往返也会减少 Token |

示例：容量轮全轮 3009 笔、10,915,891 Token，折合 3627.7 Token/笔（全轮口径）；若除以计量窗 1949 笔会算成 5601，虚高约五成。成功业务成本的分母是合格业务数，平均 Token 的分母是全部业务数，不能偷换。

## 真实成本示例

| 口径 | 读数 |
|---|---|
| 低谷混合单价 | 0.00205 元/千 Token |
| 七轮 Token | 32.22M（含校准／探针／预检） |
| 实际账单 | ¥39.10 |
| 缓存命中后有效单价 | 约 ¥1.21/百万 Token |
| 全按官方报价估算 | 约 ¥66 |

两套计价分列，不并排比较；估算值只作定位线索，不进验收读数。

## 判定边界

- “无法归因”写在表里比编原因专业；缺口必须有主人与去向。
- 不合格不只等于超时：业务未完成与时延超标可重叠，计数按同一笔业务的返回内容判断，不能把两类原因笔数相加当不合格总数。
- 慢不一定贵，贵不一定慢；两本账先分开记，是否同源等成分拆分与对照实验。
