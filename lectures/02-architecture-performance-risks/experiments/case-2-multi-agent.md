## 3. 级联故障场景

场景：`AGENT_FAULT_TARGET=logistics_agent`、`AGENT_FAULT_MODE=error`、`AGENT_MAX_RETRIES=1`、`AGENT_BREAKER_THRESHOLD=3`（物流子 Agent 持续故障，2 笔后熔断打开）。

| 分组 | 数量 | 合格率 | 降级业务 | 熔断跳过 | 超时/错误 | 路径正确率 |
|---|---|---|---|---|---|---|
| 受影响工单（物流类） | 12 | **0%** | 12/12 | 10 | 2 | 100% |
| 不受影响工单（隔离验证） | 4 | **100%** | 0 | 0 | 0 | - |
| 受影响工单内兄弟 Agent（order_agent） | - | - | - | - | - | **10/10 = 100%** |

- 在本场景覆盖范围内故障隔离成立：外部隔离验证 4/4 合格；受影响工单内已记录的 order_agent 调用 10/10 成功，未观察到该范围内的内部级联。
- 断路器在前 2 笔（error）后打开，后续 10 笔子 Agent 调用被跳过（`skipped_breaker`），不重复消耗 LLM 调用与失败成本。
- 受影响工单路径仍完整（超管规划与校验 Agent 恒定执行），故路径正确率 100%；业务因物流事实缺失而判不合格，符合“降级不虚构事实”的答复口径。

## 4. 来源与验证边界

参考课程第 02 讲的“风险登记表”及级联故障实测说明。本记录的配置、样本量和统计结果仅适用于以下验证范围。

- 已验证对象是本场景的熔断跳过、降级与故障隔离；12/12 降级不虚构事实不代表这 12 笔配送业务完成，路径正确也不代表结果合格。
- 外层超时是否向内层传播取消、内层是否在允许清理时长内停止，是另一条尚未验证的假设。稳定性场景与级联故障的历史汇总不能作为取消传播通过的证据。
- 取消传播示例中的传播规则、允许清理时长和实际观察窗口仍属待补；示例配置不构成取消机制已经通过的证据。填写方式见[风险登记表](../templates/risk-hypothesis-record.md)。
- 历史合格率沿用当时脚本和判据，未附逐笔质量、时延、安全交集明细，不能直接作为第 04 讲当前 Q 口径的逐笔证明。汇总没有附逐笔原始记录，结论仅覆盖所列配置与场景。
