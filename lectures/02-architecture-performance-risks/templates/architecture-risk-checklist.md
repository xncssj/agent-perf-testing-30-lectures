# 风险动作表

来源：课程第 02 讲“本讲交付：把风险写成下一次能验证的动作”中的“风险动作表”。风险可跨形态出现，不能逐行机械累加风险，也不能按架构降低业务验收要求。

## 参考表

| 架构形态 | 控制方式与边界 | 优先检查的性能风险 | 需要关联的证据 | 测试方案要补的动作 |
|---|---|---|---|---|
| Prompt/Chain | 模型调用顺序预设，实际次数仍受重试等影响 | 串行等待、输入输出变化、共享服务拥堵 | 步骤与请求关系、词元用量、各段耗时、业务时延、答复核验 | 固定输入版本，覆盖长输入及依赖超时，核对整链消耗 |
| Workflow/Flow | 节点和转换规则预设，路径受输入、状态和判断影响 | 低频路径长尾、汇合等待、循环边界、状态保存与恢复开销 | 路径标识、分支样本量、循环次数、状态读写和业务终态 | 补测低频分支、循环上限，按业务契约验证汇合与恢复 |
| Single Agent | 模型在动作集合与预算内选择下一步 | 无效重复、轨迹变长、上下文增长、预算未约束实际调用 | 动作与工具结果、模型和工具调用数、逐轮用量、终止原因 | 重复执行业务，覆盖无结果反馈，核验退出及退出后的活动 |
| Multi-Agent | 多个智能体通过分派、调用或交接协作，可有中心调度 | 扇出与排队、共享依赖争用、重试扩散、交接信息不一致 | 父子任务关系、派发与执行时间、队列、重试来源、数据版本 | 按实际拓扑加压，注入慢依赖，验证传播范围及协作结果 |
| Hybrid | 不同执行段采用不同控制方式，由外层规则连接 | 外层超时后内层继续执行、嵌套预算放大、状态交接遗漏 | 跨段标识、各层预算与终态、取消记录、总用量 | 分段验证后覆盖交接异常，核对整笔业务终态及消耗 |

## 项目填写区

| 项目及版本 | 业务目标与验收边界 | 实际架构及控制权 | 涉及执行段 | 判据版本与证据位置 |
|---|---|---|---|---|
| | | | | |

| 架构／执行段 | 当前风险假设 | 实际配置依据 | 需补场景或动作 | 观测位置 | 验证状态与证据 |
|---|---|---|---|---|---|
| | | | | | |

架构名称只决定优先检查点，实际结论取决于配置、业务契约和观测。检索增强是能力或业务模式，不单列为与这 5 类并列的架构。将具体假设填写到[风险登记表](risk-hypothesis-record.md)，尚未执行写“未验证”。
